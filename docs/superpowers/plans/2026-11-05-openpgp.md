# OpenPGP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repository the owner's method is one subagent per lot, the four lots in series in the main checkout.

**Goal:** Quatrelle reads OpenPGP mail (verify, decrypt), makes and keeps an account's key, learns correspondents' keys, and signs and encrypts what it sends, with nothing active until a key exists for an account.

**Architecture:** upstream ZIDAN44's OpenPGP (rPGP, `576b2770`, `896db24a`, `f32b54b0`, `775f386b`, `7e743c43`) ported beside the fork's S/MIME, file for file where the fork has the same place, plus what upstream lacks: key creation, extension, a GnuPG-readable backup, a changed-key notice, a cap on people's keys. Each lot is ported from upstream first (`~/mailcraft/merge-tools/pick.sh`, adapting where the fork differs), then the fork's additions are written test first.

**Tech Stack:** Rust 2024; rPGP `pgp = "0.21"` (`default-features = false`; `features = ["wasm"]` on wasm32), `rand_core 0.6`; the fork's egui front end; the fake IMAP and EWS servers in `crates/net/src/fakes/`.

**Spec:** `docs/superpowers/specs/2026-11-05-openpgp-design.md` (read it whole first).

## Global Constraints

- **Inactive until a key exists for the account**: no Autocrypt header, no signing, no encryption, no scheme choice shown. Reading (verify, decrypt with a key one has, learning people's keys) is always on.
- **Key form**: OpenPGP **v4**, primary **EdDSA-legacy Ed25519 (algorithm 22)** for certify + sign, subkey **ECDH Curve25519-legacy (algorithm 18)** for encryption. Not v6, not algorithms 25/27 (RFC 9580's new ones): GnuPG 2.4 can't read those.
- **Validity**: 3 years, `VALID_FOR_SECS: u64 = 94_608_000` (1,095 days), on the primary and the subkey; « Extend » re-signs for the same span from that day; the card warns from 30 days before (`EXPIRY_WARNING_SECS: i64 = 2_592_000`).
- **Backup**: armored transferable secret key, S2K usage 254, **iterated and salted SHA-256**, AES-256, readable by GnuPG 2.2 (no Argon2).
- **Secrets**: the unprotected secret key lives only in the system keychain (the pool's credentials); never in Quatrelle's files or log.
- **People's keys**: learnt only from the From address's Autocrypt header or attached `application/pgp-keys`, or a file; a newer message's key replaces an older one's, never a key imported by hand; at most **10,000** people's keys per account, the least recently used let go first, never a hand-imported one; no key servers, no WKD.
- **Changed key**: when the key learnt for an address changes, that message's security bar says so once.
- **Strings**: Quatrelle's own words (never another client's), through `tl!`/`tf!`, in all **13** catalogs of `crates/ui-egui/src/i18n/` (upstream's `tr.tsv` doesn't exist here: drop its rows).
- **The fork's rules** (`CLAUDE.md`): no `unwrap`/`expect`/`panic`/`unsafe` outside tests; every input hostile; a fuzz target per new parser; SPDX + authors header (upstream code: the MailCraft line before Didier Gaudin); at most 1000 lines per Rust file and **16 Rust files per folder** (`engine/src/session/`, `engine/src/tests/`, `mime/src/` are full; `net/src/worker/` has 15); never `mod.rs`; `cargo xtask ci` green, wasm included, before each lot ends.
- **Commits**: a straight pick keeps its upstream author (`git commit --amend --no-edit --author="Zinadin Zidan <zidan.roking@gmail.com>"`), an adaptation is Didier Gaudin's with "adapted from upstream <short>"; every message ends `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. One build at a time on this machine (`CARGO_BUILD_JOBS=4 TMPDIR=$HOME/.tq`); never launch the app; never push; no `git stash`; non-printable bytes in literals escaped.

## Review Focus

1. **A forged message carrying a new key for someone** (From spoofed, Autocrypt with another key): the key may be taken (Autocrypt's rule), but the changed-key line must show on that message, so it is not silent. Test in Task 3.3.
2. **A compression bomb or a 70 MiB "encrypted" part**: decryption stops at `quatrelle_pgp::MAX` with `Error::TooBig`, no memory blow-up, the bar says it can't be opened. Test in Task 1.1.
3. **The keychain locked or missing** (GNOME keyring not unlocked): making a key and decrypting say "the system keychain isn't available" (not "wrong key"), nothing is half-made. Test in Task 3.1.
4. **A reply to encrypted mail where one recipient's key has expired**: encryption is refused, naming that recipient; nothing goes out unencrypted unless encryption is turned off by the user. Test in Task 4.1.
5. **An account removed**: its secret keys are removed from the keychain and its people's keys file goes; no orphan secret stays. Test in Task 3.2.
