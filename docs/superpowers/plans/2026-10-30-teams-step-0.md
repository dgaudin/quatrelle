# Teams step 0: sign-in and the check on the owner's account — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the owner sign in to Microsoft 365 with the application he registers, and run
`quatrelle-cli teams check`. It prints only numbers and yes/no answers about Graph's chat API on
his real account, plus the registration guide. Delivery 1 is planned once these answers are in.

**Architecture:** OAuth for Teams joins `crates/net/src/oauth.rs`. A small Teams Graph client
(`crates/net/src/teams.rs` + `teams/graph.rs`) is the first brick of the Teams worker; the check
(`teams/check.rs`) drives it. The fake Graph server learns the Teams routes the client and the
check use. The CLI gets a `teams check` subcommand in its own file. Nothing in the engine or the UI
changes in this plan.

**Tech Stack:** Rust (workspace crates `quatrelle-net`, `quatrelle-model`, `quatrelle-cli`), the
repo's own HTTP client (`crates/net/src/http.rs`), `serde_json`.

**Spec:** `docs/superpowers/specs/2026-10-30-teams-conversations-design.md`. Read "Connection",
"Data › Keys", "Synchronisation" (the limiter and the 429 rules), "Testing › Step 0", "Risks".

## Global Constraints

- The repo's `CLAUDE.md` rules bind every task:
  - no `unwrap`/`expect`/`panic!`/`unreachable!`/`todo!` outside tests, no `unsafe`;
  - errors are `Result` through `?`;
  - everything from the network is hostile (caps, `get()`, checked arithmetic, char-boundary
    slicing);
  - at most 1000 lines per `.rs` file (split before ~800), at most 16 `.rs` per folder.
- Folder counts: `crates/net/src` has 14 `.rs` and becomes 15 with `teams.rs`. The new
  `crates/net/src/teams/` takes `graph.rs`, `check.rs` and its tests. `crates/net/src/fakes/fake_graph/`
  has 2 and becomes 3 with `teams.rs`. `apps/quatrelle-cli/src` has 1 and becomes 2 with `teams.rs`.
- Only `crates/net` does network I/O (`cargo xtask layers`).
- Graph base URL: `https://graph.microsoft.com/v1.0`. Sign-in: `https://login.microsoftonline.com/<tenant>/oauth2/v2.0/{authorize,token}`.
- Scopes, exactly:
  `https://graph.microsoft.com/User.Read https://graph.microsoft.com/User.ReadBasic.All https://graph.microsoft.com/Chat.ReadWrite https://graph.microsoft.com/Presence.Read.All https://graph.microsoft.com/Files.ReadWrite https://graph.microsoft.com/Files.Read.All offline_access`.
  `identity_scope` adds ` openid email` for a provider whose `id` is `microsoft`.
- Every message read carries a `lastModifiedDateTime` range (`$filter=lastModifiedDateTime gt …`
  or `lt …`), and every message read sends `Prefer: include-unknown-enum-members`.
- Message ids are unique only within a chat: a message is always (chat id, message id).
- **Privacy:** the check and the CLI print only counts, yes/no, HTTP status numbers and durations.
  They never print a name, an address, a chat topic, a message text, a chat or message id, or a
  user's object id, and logs never carry them either. The token stays in memory. Nothing is
  written to disk.
- Responses: JSON at most 8 MiB per response; at most 10 pages followed per listing in the check;
  a shared file's download counts bytes up to 50 MiB and keeps nothing.
- 429/503: wait `Retry-After` (capped at 20 s, at least 1 s when absent), at most 4 rounds per
  request, and count each 429 in the client's stats.
- Tests never touch a real account: the fake Graph server only. The owner runs the real check
  himself.
- Gates before each commit (from the repo root of the worktree):
  `cargo fmt --all`;
  `CARGO_TARGET_DIR=$PWD/target cargo xtask ci`;
  `CARGO_TARGET_DIR=$PWD/target-stable cargo +stable clippy --workspace --all-targets -- -D warnings`.
  Known flake: `a_big_folder_changes_all_at_once_quickly` under load. Re-run it alone, then ci.
- Commits are small, in English, "Area: what changed" plus a prose body, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. The tenant forbids user consent, or a scope is refused. The token endpoint or the redirect
   answers `consent_required` / `AADSTS65001` / `invalid_scope`, and the CLI must say "consent is
   needed: see docs/teams.md step 4" instead of a raw error. Test in Task 5.
2. Throttling during the check (a 429 every few requests) must not abort it. The check completes
   and reports the throttled count. Test in Task 4.
3. A pasted chat link with a query, a fragment, percent-encoding or junk. A good link yields the
   chat id; anything else is refused before any request. Test in Task 5.
4. An account with no chats, or a newest chat with no messages, prints zeros and does not crash.
   Test in Task 4.
5. Write probes on a chat where posting is refused (403), or that fail half-way, report "no
   (403)" and continue. Every test message the check created is soft-deleted before it ends,
   whatever failed in between. Test in Task 4.

### Task 2: The fake Graph server learns Teams

**Files:**

- Test: `crates/net/src/fakes/fake_graph/tests.rs` or a `teams` section in its `tests/` folder

**Interfaces:**
- Produces, in the fake's data (`pub(crate)`, for tests of later tasks):
  - `FakeTeams { me: FakeUser, tenant: String, chats: Vec<FakeChat>, throttle_every: Option<u32>, forbid_post: Vec<String>, shares: HashMap<String, Vec<u8>>, hits: HashMap<String, u32> }`;
  - `FakeUser { id, display_name, mail, upn }`;
  - `FakeChat { id, kind: &'static str /* "oneOnOne" | "group" | "meeting" */, topic, members: Vec<FakeUser>, read_time: String, messages: Vec<FakeMessage> }`;
  - `FakeMessage { id, from: Option<String> /* user id */, created, modified, edited: Option<String>, deleted: Option<String>, body_html, reactions: Vec<(String /* reactionType */, String /* user id */)>, attachments: Vec<(String /* contentType */, String /* contentUrl */)> }`;
  - times are RFC 3339 strings, as Graph sends them;
  - message ids are millisecond-like numbers as strings, increasing per chat.
- Routes, with responses shaped as the Graph docs show (`value`, `@odata.nextLink`):

  | Method and path | What it does |
  |---|---|
  | `GET /me` | `$select` honoured |
  | `GET /me/chats` | `$top` (default 20, max 50), `$expand=lastMessagePreview` (the newest non-deleted message's `id`, `createdDateTime`, `body`, `from`), `$orderby=lastMessagePreview/createdDateTime desc`, paging with `@odata.nextLink` |
  | `GET /chats/{id}/members` | |
  | `GET /chats/{id}/messages` | `$top` (max 50); `$orderby=lastModifiedDateTime desc` (else `createdDateTime desc`); `$filter=lastModifiedDateTime gt X` or `lt X`, else **400** (the fake insists on a range, as the plan's rule does); paging |
  | `POST /chats/{id}/messages` | creates a message from `me`; **403** for chats in `forbid_post` |
  | `PATCH /chats/{id}/messages/{mid}` | sets `edited` and `modified` |
  | `POST .../setReaction`, `.../unsetReaction` | body `{"reactionType": "👍"}`; moves `modified` |
  | `POST /users/{oid}/chats/{id}/messages/{mid}/softDelete` and the `/me/chats/...` form | sets `deleted` and `modified` |
  | `POST /chats/{id}/markChatReadForUser` | body `{"user":{"id":oid,"tenantId":tid}}` must match `me` and `tenant`, else **400**; sets `read_time` |
  | `GET /shares/{u!...}/driveItem/content` | **302** to `/download/{token}` on the fake's base, then `GET /download/{token}` serves the bytes |

  - Chat and message ids appear percent-encoded in paths: decode before matching.
  - `throttle_every: Some(n)` answers every n-th Teams request with **429** and `Retry-After: 1`.
  - `hits` counts requests per route name.

### Task 4: The check

**Files:**
- Create: `crates/net/src/teams/check.rs`
- Test: `crates/net/src/teams/tests.rs` (add a `check` section)

**Interfaces:**
- Consumes: Task 3's `TeamsClient`, `Me`, `Range`, `Stats`.
- Produces:
  - `pub struct CheckOptions { pub tenant: Option<String>, pub write_chat: Option<String>, pub hour: Option<std::time::Duration>, pub sleep: fn(std::time::Duration) }`.
    `hour: Some(d)` runs the cadences for `d` (the CLI passes 3600 s, tests pass a few seconds).
    `sleep` is `std::thread::sleep` in the CLI and a no-op or short sleep in tests.
  - `pub fn run_check(client: &TeamsClient, me: &Me, opts: &CheckOptions, say: &mut dyn FnMut(&str)) -> Result<()>`.
- What it says, in this order, one line each (the exact wording is the implementer's; the
  content is fixed):
  1. Chats: total, and by kind (one-to-one, group, meeting, other), from all pages of `chats`
     (at most 10 pages, saying "at least" when capped).
  2. The newest chat: how many messages it has, read backwards with `Range::Before(now)` (the
     server's `Date` header time, not the local clock), at most 10 pages.
  3. Across the messages read: how many carry reactions, and how many reactions are in name form
     (`like`, `heart`, `laugh`, `surprised`, `sad`, `angry`) versus Unicode form.
  4. File attachments seen (`contentType` `reference`), and whether the first one downloads
     through `download_shared` ("yes, N bytes", "no (status)", "none to try").
  5. With `write_chat`, in that chat:
     - send a first test message, text `Quatrelle check, please ignore (1/2)`;
     - react 👍 and say whether its `lastModifiedDateTime` moved (re-read with
       `Range::After(sent.lastModifiedDateTime - 1 s)`);
     - unset the reaction;
     - edit the message;
     - soft-delete it with the `/users/{oid}` form;
     - send a second message `… (2/2)` and soft-delete it with the `/me` form;
     - mark the chat read (with `opts.tenant`, else the chat's `tenantId` from `members` or
       `chats`).
     Each step prints "yes" or "no (status)". **Whatever fails, every message it sent is
     soft-deleted before `run_check` returns** (try the `/users` form, then the `/me` form).
  6. With `hour`, the approved cadences for that long:
     - `chats` first page every 10 s;
     - the newest chat's messages `After(last watermark)` every 3 s;
     - every minute, chats active in the last 7 days (measured on the server's times),
       at most 20 of them.
     Every 10 minutes (once at the end in tests), print requests and throttled so far. At the
     end, print the 429 rate.
  7. Finally `stats()`: requests and throttled.

    - accepts a raw id (`19:` prefix, then `[A-Za-z0-9._:@-]`, at most 200 chars) or a link
      `https://teams.microsoft.com/l/chat/<percent-encoded id>/…` (query and fragment ignored);
    - anything else gives `None` and the command refuses before any request.
  - `fn call_link(upns: &[String]) -> Option<String>`:
    - gives `https://teams.microsoft.com/l/call/0/0?users=<upn>,<upn>` (each `upn`

- Sign-in:
  - `authorize(&provider, "", open, 5 min)`;
  - `open` prints "Open this address to sign in: <url>" to stderr, then tries the platform opener
    without a shell (`xdg-open` on Linux/BSD, `open` on macOS, `explorer` on Windows), ignoring
    its failure;
  - the tokens live only in this process. `Tokens.tenant` feeds `CheckOptions.tenant`.
- Errors from sign-in that mean consent (`consent_required`, `AADSTS65001`, `invalid_scope` in the
  error) print "Microsoft asks for consent to these permissions: see docs/teams.md, step 4".
- `--call` reads the chat's members, builds the link and opens it with the same opener. It prints
  "opened" or the reason. It prints no member.
- `docs/teams.md` (English) is the owner's guide:
  1. The registration, steps 1–5 exactly as the spec's "The owner's registration", including the

  2. Running `quatrelle-cli teams check --client … --tenant …`.
  3. What each line means.
  4. `--write`: it posts and then deletes two test messages in the chat given, so pick a chat
     with someone who knows, or one's own notes chat. The chat link comes from Teams' "Copy link".
  5. `--hour`: it runs for an hour.
  6. `--call`.
  7. That the output holds only numbers and can be pasted back.
